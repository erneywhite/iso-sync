# Приватные каталоги

Механизм, чтобы часть образов лежала на зеркале, но **не раздавалась публично** —
с возможностью видеть их со своих IP.

## Зачем

Linux-дистрибутивы лицензии разрешают зеркалить — на том зеркало и стоит.
Образы Microsoft (Windows Server, Windows 10/11, WinPE, языковые пакеты) под это
не подпадают: скачивать их бесплатно можно, а перераздавать третьим лицам
лицензия не разрешает. Публичный листинг с ними — это ровно перераздача.

## Два слоя, и только один из них — защита

| Слой | Что делает | Это защита? |
|---|---|---|
| **`allow`/`deny` в nginx** | Файлы не отдаются с чужих адресов | ✅ Да, это и есть защита |
| **Маркер `.private` + фильтр в `index.php`** | Каталог не виден в листинге, тоталах, спарклайне и «Истории» | ❌ Нет, только витрина |

> [!WARNING]
> Один лишь маркер — **не защита**. Каталог исчезает из UI, но nginx продолжает
> отдавать `/files/<каталог>/<файл>.iso` любому, кто знает или угадает путь. Если
> каталог был публичным раньше, ссылки могли осесть в индексах поисковиков.
> Без правил в nginx приватный каталог закрыт только на вид.

Оба слоя настраиваются **одним и тем же списком IP** — держи их синхронными.

## 1. Маркер и allowlist

Файл `.private` внутри каталога делает его приватным:

```bash
touch "/www/wwwroot/iso.erney.monster/files/Windows OS/.private"
```

Пустой маркер = каталог скрыт от всех. Чтобы видеть его со своих адресов,
впиши их построчно:

```
# дом
203.0.113.42

# офис
198.51.100.0/24

# IPv6 от провайдера
2001:db8:1234::/48
```

- поддерживаются IPv4 и IPv6, одиночные адреса и CIDR-подсети;
- `#` — комментарий, работает и в конце строки;
- пустые строки игнорируются;
- **кривое правило не матчится** — приватное остаётся приватным (fail-closed).

Когда каталог показан по allowlist, он помечается в UI бейджем `🔒 private` —
чтобы не спутать его с публичной раздачей.

Признак работает **на каталог**, не на отдельный файл: так же, как его видит
nginx. Маркер лежит рядом с данными намеренно — если бы признак жил в
`config/iso-list.json`, битый конфиг молча отключил бы фильтрацию (fail-open
ровно на том, что прячем).

## 2. Закрыть каталог в nginx

В конфиг сайта (aaPanel: сайт → Конфигурационный файл), внутри `server {}`:

```nginx
# Приватный каталог: только свои адреса.
# ^~ важен: иначе location для статики по regex перехватит запрос раньше.
# Кавычки обязательны — в имени каталога пробел.
location ^~ "/files/Windows OS/" {
    allow 203.0.113.42;
    allow 198.51.100.0/24;
    allow 2001:db8:1234::/48;
    deny  all;
    autoindex off;
}

# Точечные файлы (.private и прочие) наружу не отдаём
location ~ /\. {
    deny all;
}
```

> [!IMPORTANT]
> nginx декодирует URI **до** сопоставления с `location`, поэтому в конфиге путь
> пишется с настоящим пробелом в кавычках (`"/files/Windows OS/"`), а не как
> `/files/Windows%20OS/`.

Применить:

```bash
nginx -t && nginx -s reload
```

### Если сайт за прокси (в т.ч. nginx + Apache)

`index.php` по умолчанию определяет клиента по `REMOTE_ADDR` и **не** смотрит
`X-Forwarded-For`: заголовок подделывается кем угодно, и слепое доверие к нему
открыло бы приватный листинг любому.

Симптом проблемы: правило в `.private` верное, `diag_private.php` пишет «каталог
БУДЕТ ВИДЕН», а он всё равно скрыт. Значит PHP видит не тот адрес. Проверить —
открыть `/whoami.php`: если там `REMOTE_ADDR: 127.0.0.1`, а в `X-Forwarded-For`
твой настоящий IP, диагноз подтверждён.

> [!IMPORTANT]
> **`set_real_ip_from` — директива nginx.** Если PHP работает под Apache (частый
> режим aaPanel: nginx фронтом, Apache бэкендом), она не поможет: `REMOTE_ADDR`
> в PHP ставит именно Apache. Чинить надо там, где запускается PHP.

**Вариант A (чище) — починить на уровне веб-сервера.** Для Apache это
`mod_remoteip`:

```apache
# a2enmod remoteip   (в aaPanel — LoadModule remoteip_module в httpd.conf)
RemoteIPHeader        X-Forwarded-For
RemoteIPInternalProxy 127.0.0.1
```

Для nginx-фронта без Apache:

```nginx
set_real_ip_from 127.0.0.1;
real_ip_header   X-Forwarded-For;
```

После рестарта `REMOTE_ADDR` станет настоящим — и в этом приложении, и в логах,
и во всём остальном на сервере.

**Вариант B (без правки конфигов) — `config/trusted-proxies.txt`.** Раскомментируй
там адрес прокси:

```
127.0.0.1
```

Тогда `X-Forwarded-For` читается, но **только** когда сам `REMOTE_ADDR` совпал с
доверенным адресом. Цепочка разбирается справа налево: клиентом считается первый
недоверенный адрес, поэтому подставленное клиентом значение слева не побеждает.
Пустой файл = не доверяем никому (безопасный дефолт).

> [!WARNING]
> Доверять можно только прокси, до которого не достучаться снаружи. Если
> бэкенд-порт Apache открыт в интернет, кто угодно подключится к нему напрямую
> с поддельным `X-Forwarded-For` и увидит приватный листинг. Проверь, что порт
> слушает петлю, а не `0.0.0.0`:
>
> ```bash
> ss -tlnp | grep 8181
> ```

### Нужен ли вообще Apache

Для файлового зеркала связка nginx + Apache даёт лишний хоп и лишнюю память, а
раздачу многогигабайтных ISO nginx делает эффективнее (sendfile). Если
`.htaccess` нигде не используется, nginx-only проще и заодно снимает всю эту
историю с `REMOTE_ADDR`. Но это отдельное решение по инфраструктуре — не стоит
менять его заодно с настройкой приватных каталогов.

## 3. Проверить, что закрылось

С чужого адреса (например, с телефона по мобильному интернету) ждём `403`:

```bash
curl -sI "https://iso.erney.monster/files/Windows%20OS/" | head -1
```

Маркер не отдаётся, публичное не сломалось:

```bash
curl -sI "https://iso.erney.monster/files/Windows%20OS/.private" | head -1
curl -sI https://iso.erney.monster/files/Debian/Debian_13.iso | head -1
```

Ожидаем `403` и `200`. Плюс глазами: со своего IP каталог виден и помечен
бейджем `private`, с чужого — его нет ни в листинге, ни в «Истории обновлений».

## Что оставить публичным

Не всё в `files/Windows/` требует закрытия. **virtio-win** — драйверы под
GPLv2/BSD, Red Hat публикует их открыто, перераздача разрешена. Его логично
оставить на витрине, а под замок убрать только образы самой Microsoft.
