# Приватные каталоги

Механизм, чтобы часть образов лежала на зеркале, но **не раздавалась публично**.

## Зачем

Linux-дистрибутивы лицензии разрешают зеркалить — на том зеркало и стоит.
Образы Microsoft (Windows Server, Windows 10/11, WinPE, языковые пакеты) под это
не подпадают: скачивать их бесплатно можно, а перераздавать третьим лицам
лицензия не разрешает. Публичный листинг с ними — это ровно перераздача.

Приватный каталог оставляет файлы на диске и под рукой, но убирает их из
публичного доступа.

## Два слоя, и только один из них — защита

| Слой | Что делает | Это защита? |
|---|---|---|
| **basic auth на веб-сервере** | Файлы не отдаются без пароля | ✅ Да, это и есть защита |
| **Фильтр в `index.php`** | Каталог не виден в листинге, тоталах, спарклайне и «Истории» | ❌ Нет, только витрина |

> [!WARNING]
> Один лишь фильтр в UI — **не защита**. Файлы остаются доступны по прямому URL,
> каталог перебирается, а если он уже проиндексирован — то и находится поиском.
> Без `auth_basic` смысла в приватном каталоге нет.

## Как включить

### 1. Положить маркер

```bash
touch /www/wwwroot/iso.erney.monster/files/Windows-MS/.private
```

Каталог с файлом `.private` целиком выпадает из UI. Маркер лежит рядом с
данными намеренно: если бы признак жил в `config/iso-list.json`, то битый конфиг
молча отключил бы фильтрацию — fail-open ровно на том, что прячем.

Признак работает **на каталог**, не на отдельный файл. Приватное держим отдельной
папкой — так же его закрывает и веб-сервер, по пути.

### 2. Завести пароль

```bash
htpasswd -c /www/wwwroot/iso.erney.monster/.htpasswd erney
```

Если `htpasswd` нет (пакет `apache2-utils`), хеш можно сделать через openssl:

```bash
printf 'erney:%s\n' "$(openssl passwd -apr1)" > /www/wwwroot/iso.erney.monster/.htpasswd
```

Файл `.htpasswd` должен лежать **вне** `files/` и быть недоступен по HTTP.

### 3. Закрыть каталог в nginx

В конфиг сайта (aaPanel: сайт → Конфигурационный файл), внутри `server {}`:

```nginx
# Приватный каталог: пароль + никакого автоиндекса.
# ^~ важен: иначе location для статики по regex перехватит запрос раньше.
location ^~ /files/Windows-MS/ {
    auth_basic           "restricted";
    auth_basic_user_file /www/wwwroot/iso.erney.monster/.htpasswd;
    autoindex            off;
}

# Точечные файлы (.private, .htpasswd) наружу не отдаём
location ~ /\. {
    deny all;
}
```

Затем проверить и применить:

```bash
nginx -t && nginx -s reload
```

### 4. Убедиться, что закрылось

```bash
curl -sI https://iso.erney.monster/files/Windows-MS/ | head -1
```

Ожидаем `401 Unauthorized`. Ещё две проверки — маркер не отдаётся и публичное не
сломалось:

```bash
curl -sI https://iso.erney.monster/files/Windows-MS/.private | head -1
curl -sI https://iso.erney.monster/files/Debian/Debian_13.iso | head -1
```

Ожидаем `403` (или `404`) и `200` соответственно. Плюс глазами: приватного
каталога больше нет в листинге на главной, и его имена не всплывают в блоке
«История обновлений».

## Что оставить публичным

Не всё в `files/Windows/` требует закрытия. **virtio-win** — драйверы под
GPLv2/BSD, Red Hat публикует их открыто, перераздача разрешена. Его логично
оставить на витрине, а под замок убрать только образы самой Microsoft.

Отсюда и раскладка: `files/Windows/` остаётся публичным (virtio-win), а образы MS
переезжают в отдельный приватный каталог.
