# Сборка образов Windows через UUP dump

Windows-образы нельзя просто «скачать по ссылке», как дистрибутивы Linux:
публичных зеркал не существует, потому что лицензия не разрешает перераздачу.
Зато официальные пакеты обновлений доступны напрямую с CDN Microsoft, и из них
собирается полноценный ISO. Этим занимается `build_uup.php`.

Файлы качаются **не с uupdump** — тот отдаёт только список. Сами пакеты идут с
`tlu.dl.delivery.mp.microsoft.com`, то есть с серверов Microsoft.

## Почему отдельно от update_iso.php

Сборка идёт часами и упирается в диск и процессор, тогда как `update_iso` —
быстрый проверяющий прогон. Смешивать их значит рисковать тем, что зависшая
сборка заблокирует обычную синхронизацию зеркала. Отсюда отдельный скрипт,
отдельный конфиг (`config/uup-builds.json`), отдельный лог (`logs/uup.log`) и
своя блокировка.

## Использование

```bash
# что есть в базе по запросу — нужно, чтобы задать title_pattern по факту
php build_uup.php --list='Windows Server'

# что будет собрано: сборка, редакция, объём. Ничего не качает
php build_uup.php --dry-run

# сборка всех включённых записей
php build_uup.php

# только одна запись
php build_uup.php --entry=windows-10-22h2
```

Запускать под тем же пользователем, что и остальные задачи, и **полным путём к
нужному PHP**: системный интерпретатор в `PATH` может оказаться другой сборкой
без расширений (на проде `/usr/bin/php8.3` идёт без `curl` и `mbstring`, а сайт
работает под php85).

```bash
su -s /bin/bash www -c '/www/server/php/85/bin/php build_uup.php --dry-run'
```

Прогон длинный — запускать под `screen` или `tmux`.

## Конфигурация

`config/uup-builds.json`, по записи на образ:

| Поле | Смысл |
|---|---|
| `enabled` | участвует ли запись в прогоне |
| `local_subdir` | подкаталог в `files/` — должен быть приватным |
| `name_template` | имя результата; `{build}` обязателен для ротации |
| `title_pattern` | regex по заголовку — **им задаётся канал** |
| `arch` | `amd64` / `arm64` / `x86` |
| `lang`, `edition` | язык и редакция; проверяются по факту доступных |
| `cleanup_old` | удалять прошлые версии этой же записи |

Глобально: `work_dir` (по умолчанию `.uup-work`), `file_mode` (по умолчанию
`0644`), `converter_url`.

> [!IMPORTANT]
> Канал задаётся `title_pattern`, а **не** сортировкой по дате. В базе UUP
> свежайшие по дате записи — preview-ветки, и «взять самое новое» тихо
> притащит Insider вместо стабильной GA. Заметить это можно уже постфактум,
> на зеркале.

Заголовки в базе не всегда очевидны: Windows 10 подписана как
`Feature update to Windows 10, version 22H2` — под этим именем лежит
полноценный образ, а не патч. Проверять через `--list`.

## Что доступно, а что нет

| Образ | Через UUP |
|---|---|
| Windows 11 (25H2 и другие ветки) | ✅ |
| Windows Server 2025 | ✅ редакции `SERVERSTANDARD`, `SERVERDATACENTER`, Core-варианты |
| Windows 10 22H2 | ✅ (в EOL с 14.10.2025, но ESU-ревизии ещё выходят) |
| **Windows Server 2022** | ❌ ветки 20348 в базе нет вовсе |

Server 2022 остаётся только из Evaluation Center: прямой стабильный `fwlink`,
ложится на обычный `fixed`-режим в `iso-list.json`. Ограничение в 180 дней
снимается на месте, без переустановки:

```
DISM /online /Set-Edition:ServerStandard /ProductKey:XXXXX-... /AcceptEula
```

## Надёжность

- **Целостность.** SHA1 каждого пакета из ответа API уходит в `aria2`, и тот
  проверяет файлы сам. Это единственная возможная здесь проверка: у собранного
  ISO апстримной чек-суммы не существует, поэтому порчу надо ловить на уровне
  исходных пакетов.
- **Обрыв загрузки.** `aria2` идёт с `-c`, повторный запуск продолжает с места
  остановки.
- **Обрыв после конвертации.** Если готовый ISO уже лежит в рабочем каталоге,
  конвертация пропускается — восстановление не стоит ещё сорока минут.
- **Место.** Проверяется до старта, по множителю 3.5× от объёма пакетов
  (выведен из практики: 8.14 ГБ загрузки → около 28.5 ГБ пика).
- **Параллельные запуски.** Блокировка на весь прогон: пики в десятки
  гигабайт при наложении сложились бы.
- **Ротация.** Старые версии ищутся по шаблону имени с любым номером сборки,
  поэтому задеваются только прошлые версии своей записи. Каталог общий —
  чужие образы и посторонние файлы не трогаются.

## Расписание

Примеры — в [`crontab`](../crontab). Расписание еженедельное, хотя апстрим
обновляется раз в месяц: если сборка не изменилась, прогон заканчивается сразу
после запроса каталога и ничего не качает. Так свежий билд подхватывается в
пределах недели, а не ждёт фиксированной даты.

## Приватность

Собранные образы — продукт Microsoft, и на публичную витрину они попадать не
должны. `local_subdir` обязан указывать в каталог с маркером `.private`
(см. [PRIVATE-DIRS.md](PRIVATE-DIRS.md)); сухой прогон предупредит, если маркера
нет. Напоминание: маркер убирает каталог только из листинга — раздачу файлов
закрывает `allow`/`deny` в nginx.
